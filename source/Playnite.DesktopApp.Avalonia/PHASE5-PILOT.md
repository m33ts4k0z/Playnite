# Phase 5 Avalonia Desktop pilot

This project is a side-by-side Desktop shell. It opens the same `Playnite.Core` database as the Fullscreen pilot and uses the Phase 3 loose-theme runtime. It does not replace or modify `Playnite.DesktopApp`; the WPF application remains the production Desktop path.

Run the real library with `Playnite.DesktopApp.Avalonia.exe`, optionally using `--userdatadir` or `--library-path`. Run the isolated contract harness with `--self-test`; it creates and removes a temporary 1,000-game Core database and validates 50 Desktop contracts.

The current Phase 5 tranche includes virtualized grid and list views, Core filter presets, search, installed/favorite filters, sorting, flat virtualized grouping, selection-driven details, persisted Desktop settings, plugin loading, real play/install/uninstall orchestration, notifications, and synchronous Avalonia dialogs. Its native metadata editor validates and persists the legacy writable `Game` field surface through `GameDatabase`: names and dates; user/critic/community scores; descriptions and flags; source/status; genres, platforms, categories, tags, developers, publishers, features, series, age ratings, and regions; cover/background/icon media and web links; custom game actions, library-plugin action policy, and ordered ROM records; installation state/directory/size, version/manual/HDR, runtime statistics; and pre/post/game-started scripts with their global-script policies. All four action types are editable, including emulator/profile selection, scripts, arguments, working directories, process tracking, timing, and emulator argument overrides. Local media is copied into a game-owned Core database path, replaced files follow Core cleanup, and HTTP/HTTPS background references remain remote. Bulk mode requires explicit per-field opt-in, gives each game independent action/link/ROM collections, and buffers all Core updates so unselected fields remain untouched. The same surface fulfills both plugin `OpenEditDialog` overloads. A native automatic-metadata overlay reuses Core `MetadataDownloader` for selected, filtered, or all games; persists source and field selection, skip-existing, and background-ingestion policy; exposes progress and cancellation; and imports HTTP cover/icon files into game-owned database storage. A native library-update overlay invokes Core `GameDatabase.ImportGames` for selected loaded integrations, supports all playtime import modes and customized plugin import paths, and also runs saved Core `GameScanner` configurations with their emulator/profile, ROM exclusion, platform/region discovery, relative-path, and default-completion-status behavior. It persists integration and scanner selection, optionally runs the same metadata pipeline for new games, exposes progress/cancellation/errors, synchronizes added and changed records into the live Desktop collection, and notifies plugins through `OnLibraryUpdated`. A separate installed-game overlay detects Start Menu and Microsoft Store programs, recursively scans folders, accepts individual `.exe`, `.bat`, and `.lnk` files through native pickers, filters existing launch identities, preserves Store/source and Windows-platform metadata, creates `{InstallDir}`-relative actions, extracts executable/resource icons into game-owned storage, applies default completion status, optionally downloads metadata, refreshes the live library, and notifies plugins. Fullscreen and Desktop share application host services through `Playnite.Avalonia.App`.

Remaining Desktop workstreams include manual import; plugin settings/custom elements/converters; cross-platform CEF web views; tray/window chrome; broader real-plugin testing; and the Desktop theme API 3 migration/tooling contract. Script and HDR values now persist, but the shared Avalonia action runner still needs legacy script/HDR execution policy parity.
